# H5 个人工作台

入口 `/h5/portal#t=...`，外网前缀沿用 `IMT_PUBLIC_BASE_URL`。机器人对已注册、已绑定且启用的成员发送任意文本，仅回复工作台入口。未注册用户保持原提醒，不进行激活。

## 数据与权限

- `portal_grant`：按管理员、平台、手机号保存创建权限及部门 ID / 角色 ID 范围。部门包含其下级，默认部门按官方当前部门成员关系确定。每次选择接收人及发布均读取最新官方部门树，并与当前管理员的有效名册和绑定取交集。
- `portal_task`：独立保存成员任务定义、发布者及发布时选定的接收成员。管理员模板表 `task_template` 不写入这些定义。周期实例和提交附件复用现有基础设施，通过 `pt_` 模板适配器读取任务定义。
- `portal_event`：平台消息 ID 的哈希占位，同一回调重试不重复签发、回复。消息正文不落库。
- 工作台令牌仍只存哈希，`purpose=portal`，严格 168 小时到期；提交令牌保持 `purpose=submit`，两者不可混用。
- 工作台待办每次实时检查成员状态、任务状态和有效截止窗口。驳回任务继续复用原有重交截止规则；自主上报复用一次性实例签发服务。
- 归属分级管理员通过 `/api/admin/portal-tasks` 只读监管并配置成员授权。超管不访问该面板。旧模板和实例操作入口拒绝访问成员任务。

## 发布和调度

一次性任务立即生成、投递；日 / 周 / 月任务复用执行日和动态截止计算。创建表单可选择收集文字说明、图片；任务固定免审，提交直接 `approved`。

发布请求携带稳定的 `request_id`，重放不重复创建。每条提醒发送前以实例 ID 生成唯一幂等键，先提交占位再发送，覆盖并发扫描和进程重启。为避免不确定发送结果导致重复通知，失败和发送中断不会自动重试；记录保留在 `reminder_log`。用户仍可在工作台处理已生成的任务。

同一成员可有多个管理员授权；单个任务的接收成员须落在一个共同授权管理员范围内，不能把不同管理员的数据混在一条任务中。

已有任务保留发布时的接收名单，不随部门人员变化自动扩张。后续周期仍检查该接收人在原管理员 / 角色下是否有效；撤销创建权限会阻止新建及后续调度。人员选择与新发布始终使用当前组织范围。

## 本地验证

使用项目 `.venv`，测试库仅本机 `im_task_test`：

```powershell
.\.venv\Scripts\python.exe -X utf8 -m pytest tests/test_20261118_portal.py
.\.venv\Scripts\python.exe -X utf8 -m pytest
```

专项覆盖令牌到期、用途隔离、文本入口替换、回调重试、部门与角色授权、跨管理员与平台隔离、逾期清单、免审完成、只读监管以及连续和并发调度幂等。

H5 查询使用 POST 和 `Authorization` 头，入口令牌不进入查询串。图片查看也须先验证本人发布任务或管理员监管范围；附件路径限定在 uploads 目录。页面每 30 秒刷新，并在 401 时切换到明确的过期提示页。

量密组织树复用 `IMT_ORG_ROOT_DEPT_ID`；企微复用自建应用通讯录客户端。通讯录未配置或查询失败时，授权范围查询及发布均关闭放行，不使用静态人员表兜底。无需增加长连接。
